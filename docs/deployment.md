# 部署说明

当前实例使用 Sites 托管，Cloudflare Workers 运行服务端，D1 保存词库。有道接入之外没有生成式模型调用；产品页面不包含模型工具接口。

## 当前平台适配

`.openai/hosting.json` 绑定当前 Sites 项目，D1 逻辑绑定为 `DB`。该配置路径、认证协议名属于托管平台要求，不是产品功能。平台发布时应用 `drizzle/` 迁移并提供受信任的认证头。

生产 API 必须获得可信网关注入的 `oai-authenticated-user-id` 和 email，缺失时返回 401。认证适配位于 `app/chatgpt-auth.ts`。本地登录模拟仅限 loopback 开发，不编入生产。其他平台部署需替换认证适配器或配置可信认证网关，剥离外部伪造的同名请求头；不能将裸 Worker 当作具备公开登录能力的服务。不要把本机开发服务暴露到公网。

另建 Sites 实例时，先移除复制仓库中的 `project_id`，让新实例绑定自己的数据库和认证。生产密钥通过平台环境变量或 secret 配置，不能提交 `.env`。

## 数据与迁移

数据库结构在 `db/schema.ts`。变更后运行 `npm run db:generate`，检查并提交新增迁移。已应用的迁移不可修改。词汇分类和复习记录属于词库 JSON 字段，兼容升级由 Zod 默认值处理，不需要 SQL 迁移。

当前每个账号以版本化 JSON 保存一个词库，最大 1.5 MB。最近复习记录最多保留每词 20 条。若保存超限，先按时间精简全词库最旧的逐次明细，尽量降到容量的 90%，为后续复习留出空间；响应通过 `historyTrimmed` 提示用户。累计次数、上次复习时间、下次安排和词条内容均不变。仅词条内容已超限时返回可读错误，保留原数据库数据。大规模词库部署可将词条和历史拆分为数据库表。
